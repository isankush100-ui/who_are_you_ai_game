# Who Are You? — AI Character Game

## What this version does

This version uses **10 open-ended questions**. It does NOT contain a fixed list of characters.

Flow:

Player answers 10 questions
→ Ollama reads all answers semantically
→ AI creates a 25-trait personality profile
→ another AI pass searches broadly for fictional characters
→ AI returns one final character with explanations and presentation stats
→ backend resolves a cached character image through AniList, optional TMDB, or Wikipedia

So a player could get one final character from anime, movies, TV, books, comics, games, etc., without you having to manually add every character.

## Requirements

- Python 3.10+
- A PostgreSQL database
- A Gemini API key configured as `GEMINI_API_KEY`

## Windows setup

Open PowerShell in this folder:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Start the game:

```powershell
python -m uvicorn backend.backend:app --reload
```

Open:

http://127.0.0.1:8000

## Choosing another Gemini model

PowerShell:

```powershell
$env:GEMINI_MODEL="your-model-name"
python -m uvicorn backend.backend:app --reload
```

## Render deployment

Use the following start command in Render:

```text
python -m uvicorn backend.backend:app --host 0.0.0.0 --port $PORT
```

Configure `DATABASE_URL` and `GEMINI_API_KEY` as Render environment variables.
Keep local `.env` files out of Git; the root `.gitignore` already excludes them.

## Important design choice

The AI is asked to build a structured personality profile first. It is NOT asked to simply guess a character directly from keywords.

The character-discovery step is separate. This makes the system easier to improve later.

## Limitation

Because the character list is generated by an LLM, the candidates are not a scientifically measured result. The game should describe them as "fictional character resemblance."

Character images:
- AniList is tried first for characters associated with anime/manga media.
- TMDB is tried next when `TMDB_API_KEY` is configured; it verifies a cast role in a matching title.
- Wikipedia's public MediaWiki API is the final external lookup.
- Failed lookups use the local `frontend/assets/characters/default.svg` fallback.
- Results are cached in memory by normalized character and universe.

No key is required for AniList or Wikipedia.
TMDB attribution appears on results when a TMDB image is used.
